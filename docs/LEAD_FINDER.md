# Lead Finder — поиск холодных игроков в комментариях и Discord

Сервис читает комментарии под тематическими видео, находит людей, которые
**недовольны своим сервером**, **ищут сервер** или **хотят начать играть**, и складывает их
в базу: ссылка на профиль + сам комментарий + прямая ссылка на комментарий + видео.
Дальше вы сами подписываетесь и пишете людям.

Сервис **только читает**: YouTube — через официальный Data API, Discord — через официального
бота. Он не логинится в ваши аккаунты, ничего не лайкает, не комментирует и не пишет людям.

## Быстрый старт (10 минут)

1. `.env`: `YOUTUBE_API_KEY=...` (как получить — ниже). По желанию `ANTHROPIC_API_KEY`,
   `DISCORD_BOT_TOKEN`, `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID`.
2. `npm run ui:build && npm run leads` → откройте http://localhost:3124/campaigns.
   (Или вместе с видеофабрикой: `npm run dev`, страницы **Campaigns** и **Leads**.)
3. **Campaigns → Новая кампания**: игра, 2–3 поисковых запроса, 3–10 каналов обзорщиков или
   конкурентов (`@handle` или ссылка), названия конкурентов → **Сканировать**.
4. **Leads**: очередь новых лидов, самые сильные сверху. «открыть комментарий» → ответили или
   написали человеку → ✓. Мусор → ✗. Обработанный лид уходит из очереди.
5. Через 1–2 недели посмотрите **Campaigns → Что работает**: какие сигналы приводят людей,
   а какие дают отказы, какие видео и каналы дают больше всего лидов. Уберите лишнее.

Для постоянной работы: `LEAD_FINDER_SCAN_INTERVAL_MINUTES=360` (автоскан каждые 6 ч) и
Telegram-уведомления о горячих лидах. Тот, кто спросил «посоветуйте сервер» час назад, ещё выбирает.

## Насколько точно он находит

Замерено на размеченном наборе реалистичных комментариев и Discord-сообщений
(`src/lead-finder/classifier/eval-corpus.ts`, проверка `npm run leads:eval`):

* **Словарь без Claude.** Первая версия: точность 71%, полнота 56%. На свежих фразах,
  которых словарь не видел, после переработки: точность 100% (ничего лишнего), полнота 50%.
  То есть он ловит явные формулировки и пропускает примерно половину «живых».
  Найденные пропуски потом добавлены в словарь. Теперь на обоих наборах 100/100, но это
  уже подгонка под известные фразы, а не прогноз.
* **Claude** нужен для полноты: «устал от этого проекта», «где сейчас нормально играть?»,
  сарказм, опечатки. Перед Claude стоит фильтр: он пропускает все лиды из набора и
  отсекает 55–70% мусора, поэтому платите только за осмысленные комментарии.
  Сравнить модели по качеству и токенам:
  `ANTHROPIC_API_KEY=... LEAD_FINDER_LLM_MODEL=claude-haiku-5-5 npm run leads:eval`.
* Добавляйте в набор реальные комментарии из своей ниши (и ошибки, которые заметили):
  тесты не дадут их сломать при следующих правках.

## Как это работает

```
кампания (запросы, каналы конкурентов, видео, Discord-серверы/каналы)
      │
      ▼
YouTube Data API / Discord Bot API ──► комментарии и сообщения (новые с прошлого скана)
      │
      ▼
правила (словарь RU/EN, бесплатно) ──► [опционально] Claude уточняет спорные
      │
      ▼
SQLite: лиды + комментарии + статусы ──► REST /api/leads ──► ваша панель / CSV
```

* **Инкрементально**: при повторном скане читаются только комментарии новее прошлого;
  каждый комментарий классифицируется один раз.
* **Дедупликация по автору**: один человек = один лид, все его комментарии прикреплены к нему.
* **Квота**: поиск стоит 100 единиц, остальные вызовы — 1. Бюджет на сутки задаётся
  `LEAD_FINDER_DAILY_QUOTA` (у Google по умолчанию 10 000/сутки на проект).
  Каналы конкурентов читаются через плейлист загрузок — 2 единицы вместо 100.

## Запуск

1. Google Cloud Console → создать проект → включить **YouTube Data API v3** → Credentials → **API key**.
2. В `.env`:
   ```
   YOUTUBE_API_KEY=...
   # опционально — точнее отсев мусора и сарказма:
   ANTHROPIC_API_KEY=...
   LEAD_FINDER_SCAN_INTERVAL_MINUTES=360   # автоскан каждые 6 часов
   LEAD_FINDER_API_TOKEN=длинный-секрет     # если API торчит наружу
   ```
3. Варианты запуска:
   * вместе с видеофабрикой — `npm run dev` / `npm start`, API на `/api/leads`, страница **Leads** в UI;
   * отдельно, без рендера видео и ключа Pexels — `npm run leads` (порт `LEAD_FINDER_PORT`, по умолчанию 3124).

Нужен Node.js ≥ 22.5 (встроенный `node:sqlite`, без нативных зависимостей).

## Кампания через API

Обычно кампании создаются на странице **Campaigns**. API нужен, если вы встраиваете сервис в свою панель.

```bash
curl -X POST localhost:3123/api/leads/campaigns -H 'content-type: application/json' -d '{
  "name": "GTA 5 RP — RU",
  "game": "GTA 5 RP",
  "queries": ["лучший сервер гта 5 рп", "обзор серверов gta 5 rp", "на какой сервер гта рп пойти"],
  "channelIds": ["UCxxxxxxxxxxxxxxxxxxxxxx"],
  "videoIds": ["https://www.youtube.com/watch?v=xxxxxxxxxxx"],
  "competitorNames": ["Majestic", "Arizona", "Radmir"],
  "ownServerName": "Название вашего сервера",
  "extraKeywords": ["семья ищет игроков", "где норм экономика"],
  "language": "ru",
  "regionCode": "RU",
  "publishedWithinDays": 30,
  "maxVideosPerQuery": 15,
  "maxCommentsPerVideo": 500,
  "minScore": 40
}'

curl -X POST localhost:3123/api/leads/campaigns/1/scan   # скан сейчас, вернёт отчёт
```

* `channelIds` принимает `UC…`, `@handle` или ссылку на канал.
* `maxCommentAgeDays` (по умолчанию 60): более старые комментарии не считаются лидами, даже под
  «вечнозелёным» видео. Заодно скан раньше останавливается и экономит квоту.

Что даёт лучший результат:
* **Каналы конкурентов и обзорщиков серверов** (`channelIds`) — самая «тёплая» аудитория и дешёвая квота.
* **Видео про проблемы**: «вайп», «почему ушёл с …», «топ серверов 2026», «какой сервер выбрать».
* `competitorNames` — сервис отметит, с какого сервера человек уходит (видно в `/stats`).

## API (`/api/leads`)

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/status` | ключи, квота за сегодня, идёт ли скан |
| GET/POST | `/campaigns` | список / создать |
| PUT/DELETE | `/campaigns/:id` | изменить / удалить |
| POST | `/campaigns/:id/scan` | скан одной кампании (ждёт результат) |
| POST | `/scan` | скан всех включённых в фоне |
| GET | `/scans` | последние отчёты |
| GET | `/discord` | ссылка-приглашение бота + серверы и каналы, которые он видит (ID для кампаний) |
| GET | `/` | лиды: `status`, `category`, `platform`, `minScore`, `campaignId`, `search`, `sort=score\|recent`, `limit`, `offset` |
| GET | `/export.csv` | те же фильтры, CSV (открывается в Excel/Google Sheets) |
| GET | `/stats` | статусы, категории, **какие серверы ругают**, **какие видео/каналы дают больше лидов**, частые жалобы |
| GET/PATCH/DELETE | `/:id` | лид со всеми комментариями / `{status, notes, tags}` / удалить |
| POST | `/notify/test` | тестовое сообщение в Telegram |
| POST | `/import` | загрузить комментарии из другого источника (TikTok и т.д.) |

Статусы: `new → in_progress → contacted → subscribed → converted`, либо `rejected`
(отклонённый лид не вернётся как новый — автор уникален).

Если задан `LEAD_FINDER_API_TOKEN`, все запросы должны слать `Authorization: Bearer <token>`
(веб-страницы спросят токен один раз). Если панель на другом домене: `LEAD_FINDER_CORS_ORIGIN=https://panel.example`.

## Уведомления в Telegram

1. Создайте бота у @BotFather → `TELEGRAM_BOT_TOKEN`.
2. Напишите боту `/start`, откройте `https://api.telegram.org/bot<token>/getUpdates`, возьмите
   `chat.id` → `TELEGRAM_CHAT_ID` (можно id группы команды).
3. `LEAD_FINDER_NOTIFY_MIN_SCORE=70`. После каждого скана приходит одно сообщение с новыми
   лидами от этого балла: профиль, текст, ссылка на комментарий. Проверка подключения:
   кнопка-чип «Telegram» на странице Campaigns.

Сообщения уходят только вам. Лидам бот ничего не пишет.

## Discord

Discord читается **ботом**, которого админ сервера добавил к себе. Бот видит только
серверы, куда его пригласили: ваш сервер, партнёрские сообщества, сервера семей/кланов,
стримеров и форумы, чьи админы согласились.

Чужие серверы, куда бота не пустили, сервис не читает. Парсинг через личный аккаунт
(«селф-бот», токен пользователя) запрещён правилами Discord, и за него банят аккаунт навсегда.
Такой режим не поддерживается и не будет.

### Настройка (5 минут)
1. https://discord.com/developers/applications → **New Application** → вкладка **Bot** →
   **Reset Token** → токен в `.env` как `DISCORD_BOT_TOKEN`.
2. Там же, на вкладке **Bot**, включите **Message Content Intent**. Без него Discord отдаёт
   сообщения без текста. Пока бот стоит меньше чем на 100 серверах, хватает просто включить
   переключатель; на большем числе Discord требует верификацию.
3. `GET /api/leads/discord` → в ответе `inviteUrl`. Отправьте ссылку админу сервера-партнёра.
   Права бота минимальные: просмотр каналов и чтение истории, писать он не может.
4. После добавления тот же `GET /api/leads/discord` покажет серверы и каналы с их ID.
   Впишите нужные в кампанию:

```json
{
  "name": "Discord партнёры",
  "game": "GTA 5 RP",
  "discordGuildIds": ["111111111111111111"],
  "discordChannelIds": ["222222222222222222"],
  "discordExcludeChannelIds": ["333333333333333333"],
  "maxMessagesPerChannel": 1000,
  "publishedWithinDays": 30,
  "competitorNames": ["Majestic", "Arizona"]
}
```

* `discordGuildIds` — читаются все текстовые каналы, каналы объявлений, форумы и активные ветки,
  к которым у бота есть доступ. Закрытые каналы просто пропускаются.
* `discordExcludeChannelIds` — исключить #правила, #staff, мемы. Исключённый форум пропускается
  вместе со всеми постами.
* Первый скан берёт сообщения за `publishedWithinDays`. Каждый следующий продолжает с
  последнего прочитанного сообщения. Большой архив разбирается порциями по
  `maxMessagesPerChannel`, без пропусков.
* Сообщения ботов, вебхуков и системные сообщения отбрасываются.
* В базе: ссылка на профиль `https://discord.com/users/<id>` (открывается у тех, у кого с
  человеком общий сервер) и прямая ссылка на сообщение.
* Лимиты Discord соблюдаются: при ответе 429 сервис ждёт столько, сколько попросил Discord.

**Политика Discord для разработчиков**: сообщения можно использовать только для заявленной цели
бота. Скажите админам серверов-партнёров, что бот ищет игроков, которые ищут сервер. По запросу
человека удаляйте его через `DELETE /api/leads/:id`.

## TikTok

У TikTok нет публичного API комментариев для коммерческих проектов (Research API — только
для академических исследователей), а автоматический сбор через сайт/приложение нарушает их
условия использования и быстро ведёт к блокировке аккаунта. Поэтому TikTok подключён через
**импорт**: тот же классификатор и та же база, а источник — любой, который вам доступен легально
(ручная выгрузка, ваш помощник, лицензированный поставщик данных).

```bash
curl -X POST localhost:3123/api/leads/import -H 'content-type: application/json' -d '{
  "campaignId": 1,
  "comments": [{
    "platform": "tiktok",
    "commentId": "7301...",
    "videoId": "7300...",
    "videoUrl": "https://www.tiktok.com/@author/video/7300...",
    "authorId": "user123",
    "authorName": "user123",
    "authorUrl": "https://www.tiktok.com/@user123",
    "text": "посоветуйте сервер, на старом одни читеры"
  }]
}'
```

## Классификация

* **Правила** (`src/lead-finder/classifier/rules.ts`) — словарь фраз RU/EN с весами + отсев спама
  (ссылки, промокоды, «заходи на мой сервер»). Работают всегда, бесплатно.
* **Claude** (если задан `ANTHROPIC_API_KEY`) — получает только комментарии, где есть хоть
  какой-то сигнал про сервера/игру (`LEAD_FINDER_LLM_PREFILTER=signals`), батчами по 40, и
  возвращает категорию, скор 0–100, упомянутые сервера и причину по-русски.
  Модель по умолчанию `claude-opus-5-5`; для большого потока дешевле `LEAD_FINDER_LLM_MODEL=claude-haiku-5-5`.
  Для Opus/Sonnet включён серверный fallback при отказе модели.

## Данные и приватность

Сохраняются только имя, ссылка на профиль и текст комментария/сообщения: публичные на YouTube
и видимые участникам на серверах, куда пригласили Discord-бота.
`DELETE /api/leads/:id` удаляет человека полностью — используйте, если кто-то попросит.
Пишите людям вручную и по одному: массовые одинаковые сообщения/комментарии платформы
считают спамом.
